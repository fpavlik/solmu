# Data files and schemas

Same content as `IMPLEMENTATION_PLAN.md` section 5, with the examples taken from the shipped Finland files and the optional fields added by the implementation. Validation errors name file, record and field.

## `nodes.csv`

```
id,name,kind,lat,lon,population,country,tags
FI-18,Uusimaa,region,60.25,24.95,1730000,FI,sea=gulf_of_finland
port-hamina-kotka,HaminaKotka,port,60.47,26.95,,FI,sea=gulf_of_finland;host=FI-09
src-porvoo-refinery,Porvoo refinery,source,60.31,25.55,,FI,host=FI-18
```

`kind` is one of `region | port | source | hub`. `tags` is `key=value;key=value`. Hubs may carry
`holds=medicine|food` (pipe-separated commodity ids): those commodities are stocked at the hub
when they are `via_hubs`; a hub without `holds` is a pass-through.
Empty population for non-regions. `country` is optional (default empty).

## `edges.csv`

```
id,from_node,to_node,mode,capacity_per_day,transit_days,cost_per_tonne,bidirectional
road-FI-18-FI-19,FI-18,FI-19,road,20000,1,1.28,true
rail-FI-18-FI-06,FI-18,FI-06,rail,12000,1,0.54,true
sea-port-turku-FI-01,port-turku,FI-01,sea,800,1,1.5,true
```

Optional `commodities` column: pipe-separated commodity ids (`fuel|food`) the edge may carry;
empty or absent = all commodities. Ids are checked against the catalogue when the simulation
is built.

`mode` is `road | rail | sea`. `capacity_per_day` in tonnes/day across all
commodities. `transit_days >= 1`. `bidirectional` defaults to true; `Network.arcs()`
expands it into two directed arcs (`<id>` and `<id>:rev`), each with the full
capacity. Ports connect to their host region with a
short edge; the port node carries import capacity via `supply.csv`.

## `commodities.json`

```json
{
  "commodities": [
    {"id": "medicine", "name": "Medicines", "unit": "t", "priority": 1, "per_capita_kg_per_day": 0.01},
    {"id": "food",     "name": "Food",      "unit": "t", "priority": 2, "per_capita_kg_per_day": 2.0},
    {"id": "fuel",     "name": "Fuel",      "unit": "t", "priority": 3, "per_capita_kg_per_day": 4.0}
  ],
  "default_stock_days": 2
}
```

Optional per commodity: `via_hubs` (default false: ports ship to hubs only and regions are fed
from hubs only), `hub_stock_days` (override of the catalogue value) and `shortage_cost_per_tonne`
(default 0: price of one tonne of unmet demand, summed into `summary["shortage_cost"]` and
`total_cost`). Optional in the catalogue:
`hub_stock_days` (default 7, days of served demand held at hubs, plus hub lead time),
`import_redirect_delay_days` (default 2) and `import_backlog_loss_fraction_per_day`
(default 0, range [0, 1]); see `docs/MODEL.md`.

Lower `priority` is served first when capacity is scarce. `default_stock_days` is
the usable cover held per region (default 2). Optional per commodity: `perishable_days`
(parsed, unused in v0); `per_capita_kg_per_day` defaults to 0.

## `demand.csv`, `supply.csv`

`node_id, commodity_id, tonnes_per_day`; `supply.csv` has an optional fourth column
`max_tonnes_per_day` (port handling capacity, default `tonnes_per_day` so no headroom and no
redirection; must be >= `tonnes_per_day`; an empty cell means default).

Demand: regions, generated by `scripts/build_demand.py` from population and
per-capita rates, then committed so it can be reviewed and overridden.
Supply: ports (import capacity) and sources (production).

## `policies/*.json`

```json
{
  "id": "finland_statutory",
  "name": "Finland — statutory stockpiling (approximate)",
  "description": "...",
  "min_stock_days": {"food": 90, "fuel": 120, "medicine": 90},
  "stock_holder": {"food": "state", "fuel": "companies", "medicine": "companies"},
  "release": {
    "trigger": "on_disruption",
    "disruption_threshold": 0.3,
    "disruption_persistence_days": 1,
    "delay_days": 2,
    "max_release_fraction_per_day": 0.1
  },
  "emergency_budget": 50000000,
  "holding_cost_per_tonne_day": {"food": 0.5, "fuel": 0.3, "medicine": 2.0}
}
```

`release.trigger` is `shortage | manual | always | on_disruption`. `release.delay_days` defaults
to 0 and `max_release_fraction_per_day` to 1 (range 0-1). `on_disruption` (anticipatory release
when the national import offer falls) uses `release.disruption_threshold` (0-1, default 0.3:
release starts when the import drop exceeds it) and `release.disruption_persistence_days`
(integer >= 1, default 1: consecutive days the drop must exceed it before the `delay_days`
countdown starts); both are ignored by the other triggers. `stock_holder` is
informational in v0. Policy files are plain JSON (no comments, no `_` in numbers).

Optional fields:
- `target_stock_days` (object commodity id to days, default absent): usable cover
  per commodity, replacing `default_stock_days`; the engine adds the lead time.
- `capacity_rental_cost_per_tonne_day` (default 10.0): price per tonne of extra
  edge capacity per day for the `AddCapacity` action.
- `strategic_stock_at` (object commodity id to a list of holders, default absent = all of it
  at regions): where the strategic stock of a commodity is physically held. Each holder has
  `kind` (`region` | `hub` | `node`), `share` (0-1; shares of one commodity sum to 1), and for
  `node` a `node_id` (a `source` node) and optional `requires_processing` (0-1, default 0: the
  part, e.g. crude at a refinery, that can only be released while the node runs) and optional
  `release` (`policy`, the default: released by the policy rule; `automatic`: drawn as needed
  without a decision, for `node` holders without `requires_processing`). `hub` needs a
  `via_hubs` commodity with hubs that hold it. Example:
  `{"medicine": [{"kind": "hub", "share": 0.7}, {"kind": "region", "share": 0.3}],
  "fuel": [{"kind": "node", "node_id": "src-porvoo-refinery", "share": 0.4, "release": "automatic"},
  {"kind": "node", "node_id": "src-porvoo-refinery", "share": 0.6, "requires_processing": 0.4}]}`.
  See `docs/MODEL.md`, "Strategic stock holders".

## `scenarios/*.json`

```json
{
  "id": "hamina_winter_closure",
  "name": "Winter closure of HaminaKotka",
  "description": "...",
  "horizon_days": 30,
  "demand_noise_fraction": 0.0,
  "events": [
    {"day": 3,  "type": "node_capacity", "node_id": "port-hamina-kotka", "factor": 0.0, "until_day": 17},
    {"day": 3,  "type": "node_capacity", "node_id": "port-helsinki",     "factor": 0.6, "until_day": 20},
    {"day": 3,  "type": "edge_capacity", "edge_id": "rail-FI-16-FI-09", "factor": 0.5, "until_day": 10},
    {"day": 5,  "type": "demand",        "node_id": "FI-02", "commodity_id": "food", "factor": 1.5, "until_day": 9}
  ]
}
```

A `demand` event may use `"node_id": "*"` for all regions.

Event types: `node_capacity` (scales supply offered at the node; optional `commodity_id`, default
absent = all commodities, limits the event to one commodity), `edge_capacity` (scales both
directions of the edge), `demand` (scales a region's demand) and `stock_target`
(`node_id` a region, a hub or `"*"` for all regions and hubs; optional `commodity_id`, absent = all;
scales the order-up-to stock target in the window, so nodes order more (factor above 1) or run
stock down (below 1); initial stocks are unchanged):

```json
{"day": 0, "type": "stock_target", "node_id": "*", "commodity_id": "food", "factor": 1.5, "until_day": 3},
{"day": 4, "type": "node_capacity", "node_id": "port-turku", "commodity_id": "fuel", "factor": 0.0, "until_day": 19}
```

`factor` is applied multiplicatively to the base value for the inclusive
window `[day, until_day]`; multiple events on the same target multiply. Event
targets are checked against the network when the simulation is built.

`demand_noise_fraction` (optional, default 0, range [0, 1)): each tick every region
and commodity demand is multiplied by `1 + U(-f, f)`, drawn from the seeded generator.

## `SOURCES.md`

One line per number or group of numbers: what it is, value, source (URL or
reasoning), confidence (`measured` / `estimated` / `placeholder`). No number in
`data/` without a line here, including placeholders.
